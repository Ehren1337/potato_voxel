## Bugs

### BUG-1 — GPU/compositor crawl ~34s after first voxel render (HIGH)

**Evidence** — Steam Deck, linux 1.7.7, session `20260816-202329` (AMD vangogh):

- First voxel scene rendered 20:24:31 (render avg 0.6ms, texMB 17.9).
- Crawl 20:24:38 → 20:25:12: `frame avg` 539 → 4114 → 3230 → 3768 → 3164 →
  2970ms (3–4s/frame).
- During the crawl `render avg` is pinned at **42.3ms** and texMB stable at
  **18.4** → the cost is GPU-side (driver/compositor), not CPU render time and
  not texture eviction.
- Recovery at 20:25:17, then a permanent 16.7ms (60fps) for the rest of the
  session.
- **Cross-platform**: same signature as the Pi case in the prior review
  (session `20260816-010255`) — confirms this is not platform-specific. 309
  STALL-tagged lines total across all 1.7.5+ files.

**Likely cause**: a driver shader/texture upload burst when the first full scene
renders — a single GPU upload spike that blocks every frame for ~34s.

**Fix plan** (implemented in 1.7.8-dev):
- Pre-warm / prime the first chunk's textures before the first full render
  (small upload burst instead of the full scene's).
- Render-skipping: drop the voxel draw for up to N frames while a stall is in
  progress so input stays responsive.
- STALL tags now carry driver/vendor identity + shader-compile timing to
  confirm the root cause on the next review.
- Engine-side: async texture upload / shader compile remains open (engine
  PR #1454 thread).

### BUG-2 — Save-write & map-enter freezes on the main thread (MEDIUM)

**Evidence**:
- Android 1.7.5 `20260816-193229`: worstFrame **8436ms**; `20260816-193117`:
  **5217ms**; `20260816-200112` (1.7.6): slowLoads=14, worstFrame 2575ms.
- Prebuild cooperative-slice overshoots are common: android `20260816-192746`
  = 81 overshoots (worstResumeMs 1538 on SAFFRON_CITY/body), windows 1.7.6
  `20260816-200646` = **428** overshoots, switch `20260816-171911` = 224 — the
  30ms slice is routinely exceeded.
- `(sync)` slow loads on entry frames: VIRIDIAN_CITY/full 443–1236ms — these
  run on the entry frame and ARE freezes.
- Switch 1.7.6 `20260816-171911`: 59 STALL lines at `path=never level=0` with
  `render avg 0.0ms` — main-thread map-enter/save/prebuild freezes, **not** GPU
  (distinct from BUG-1).

**Fix plan** (implemented in 1.7.8-dev):
- Push save-writing off the entry frame (defer to idle frames / background).
- Tighten the CachePrebuild cooperative budget: reduce the per-slice budget and
  pre-empt mid-job so overshoots collapse toward zero.
- Throttle/defer the cold-flash resume scan (worstResumeMs 1.5s) to the first
  idle frame(s), in small cooperative chunks.

### BUG-3 — `storage read "nil": invalid_key` warn noise at prebuild finish (LOW, root-caused)

**Evidence**: linux 1.7.5 `20260816-192317`, ~70 warns collapsed between
`prebuild 454/454 done` (19:24:36.288) and `manifest written` (19:24:36.422).

**Root cause pinned**: `MeshCache.writeManifest` → `updateCompression(records)`
calls `safeMetaFingerprint(record.aux, ...)`; `record.aux` is **nil** for jobs
whose aux save failed (the documented "aux is OPTIONAL" path), and
`metaFingerprint(nil, prefix)` → `readTable(nil)` → `store_.read(_, _, nil)` →
engine `invalid_key`. Counts as storageWarns (not storageFails) — harmless but
noisy and misleads triage.

**Fix plan** (implemented in 1.7.8-dev): guard nil keys in
`metaFingerprint`/`readTable` (return nil before any storage call), or skip nil
`record.aux` in `updateCompression`. The warn-on-invalid_key path for genuinely
bad legacy keys is preserved.

### BUG-4 — 44s stall on app resume (INFORMATIONAL, not voxel)

**Evidence**: android 1.7.5 `20260816-192746` worstFrame 44555ms. Voxel=OFF
session. Prebuild finished READY at 19:31:30; the 44s frame occurred at 19:36:49
after a ~5-minute frame-log gap → the app was backgrounded; the stall is OS
resume, not prebuild.

**Action**: no code change. Noted here so it is not misread as a regression.

## Optimizations

### OPT-1 — Auto-send cadence fixed at 90s even when idle (MEDIUM, bandwidth)

Every session ships exactly every **90.0s of game time**, even with no new ring
lines. 32 files / 2.2MB total; 1KB–20KB POSTs. **Fix** (implemented in
1.7.8-dev): back off when the ring is unchanged — send only on new lines, with a
5-minute idle heartbeat cap. Reduces battery/bandwidth on mobile.

### OPT-2 — Server memory & delta handling (MEDIUM, loghook repo)

- `sessions` Map holds full merged docs forever; no in-memory eviction of idle
  sessions (the hourly sweep only deletes files).
- No delta compression server-side (client ring is already delta for 1.7.5+).
- **Fix** (implemented): evict idle session docs from the Map after flush +
  retention window; keep file-based merge. Gzip of POST bodies deferred (no
  dependency in the server's current setup).

### OPT-3 — cacheMisses ≈ 2×jobs on full rebuilds (LOW, explainable)

Sessions with full prebuilds show misses ≈ 2×jobs (446 jobs → 892 misses;
449 → 889; 444 → 888) because terrain + water are counted per job. This is the
**expected full-rebuild signature** after the 1.7.6 identity/key change, not a
bug. Sessions with partial builds show small miss counts. Documented; no fix
required.

### OPT-4 — Threaded prebuild workers (FUTURE)

1.7.8 threaded workers TBD; engine PR #1454. The cooperative-slice approach
works but overshoots remain (BUG-2) — thread off-build when available. See
`docs/threaded-geometry-design.md`.
